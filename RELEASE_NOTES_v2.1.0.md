# NitroFrame v2.1.0

Обязательное обновление безопасности. Сервер больше не отвечает клиентам версии
ниже 2.1.0 — обновление нужно всем.

## Обход правил выдачи доступа

- Пробный период теперь привязан и к устройству, и к аккаунту. Раньше запись о
  триале ключевалась только по HWID, а HWID приходит от клиента и подделывается
  обычным HTTP-запросом — то есть триал можно было получать бесконечно, меняя
  строку. Теперь оба ограничения независимы: «один триал на железо» и «один
  триал на аккаунт», оба на уровне базы данных.
- Вход через Telegram больше не выдаёт триал в обход учёта. Прежде для
  Telegram-аккаунта без HWID лицензия создавалась напрямую, минуя журнал
  триалов и любую привязку к устройству: новый Telegram-аккаунт (секунды работы,
  без почты) означал новый триал. Теперь путь один для всех — без устройства
  триал не выдаётся.
- Максимальный срок заморозки ограничен 30 днями. Раньше разморозка продлевала
  подписку ровно на то время, которое её держали замороженной, без верхнего
  предела: год заморозки давал год подписки. Заодно замороженная лицензия больше
  не «висит активной» бесконечно — по истечении срока заморозки она истекает,
  как обычная.
- Ограничение 90 дней применялось к каждой отдельной выдаче, но не к итогу:
  продления считались от текущего конца, поэтому десять выдач по 90 дней давали
  900 дней. Теперь итоговый срок не уходит дальше общего горизонта в 365 дней.

## Обход второго фактора и токенов

- Промежуточный токен «пароль верен, жду код из письма» больше не работает как
  обычный токен доступа. Он подписывался тем же ключом и содержал идентификатор
  пользователя, поэтому его можно было отправить как обычную авторизацию и
  войти без второго фактора. Теперь у токенов второго фактора и токенов действия
  отдельные ключи подписи и отдельная аудитория.
- «Это Telegram-аккаунт» определяется записью в таблице Telegram-аккаунтов, а не
  видом адреса. Проверка по началу строки «tg» считала таким аккаунтом любую
  почту, начинающуюся на эти буквы (например, `tgor@gmail.com`), и такой аккаунт
  проходил вход вообще без второго фактора.
- Токен разового действия проверяется вместе с подписью до чтения его
  содержимого. Раньше содержимое читалось без проверки, и на битой строке сервер
  отвечал внутренней ошибкой.
- Погашенные разовые токены хранятся в базе, а не в памяти процесса. После
  перезапуска сервера ещё живые токены можно было предъявить второй раз.

## Гонки и одноразовость

- Подарочный код захватывается атомарной операцией с проверкой числа затронутых
  строк. Прежняя версия открывала транзакцию, но не блокировала строку: два
  одновременных запроса оба видели код активным и выдавали по лицензии каждому.
- Активация подарочного кода теперь требует входа в аккаунт: раньше лицензия
  могла быть создана без владельца, и восстановить, кому она принадлежит, было
  нечем.
- Подтверждение оплаты блокирует строку платежа до чтения его статуса. Блокировка
  бралась по пользователю (и только если он известен) уже после чтения статуса,
  поэтому две доставки одного уведомления могли продлить подписку дважды.

## Ограничение частоты и заголовки

- Реальный адрес клиента больше не берётся из заголовка, который клиент может
  подставить сам. Разбор заголовков обратного прокси включён со списком
  доверенных адресов; сам прокси передаёт ровно один адрес и определяет
  настоящий адрес через заголовок Cloudflare. До этого лимит попыток входа
  снимался подстановкой произвольного адреса.
- Ограничение проверки лицензии считается по адресу, а не по клиентскому
  заголовку с идентификатором устройства, который менялся одной строкой.
- Добавлен общий потолок запросов на адрес: эндпоинт без явной политики больше
  не остаётся без ограничений.
- Добавлены HTTP security headers: `X-Content-Type-Options`, `X-Frame-Options`,
  `Referrer-Policy`, `Content-Security-Policy`, политики Cross-Origin. Срок HSTS
  поднят до года с поддоменами. В прошлом релизе эти заголовки были объявлены,
  но в коде их не было.

## Журнал и мелкие исправления

- Все операции со сроком доступа пишутся в журнал: создание и отзыв подарочных
  кодов, их активация, ручная выдача, отзыв лицензии, заморозка и разморозка,
  выдача триала, блокировка и удаление аккаунтов, смена роли, сброс привязки
  устройства. Раньше логировалась только успешная оплата, и восстановить историю
  по пользователю было нечем.
- Проверка версии клиента стоит на всех эндпоинтах приложения, а не только на
  входе. Прежний гейт обходился за один шаг: старая сборка с сохранённой сессией
  или вход через Telegram проверку не проходили вовсе.
- Страница подтверждения почты больше не показывает ошибку после успешного
  подтверждения (условие проверки результата не выполнялось никогда).
- Удаление аккаунта администратора больше не нарушает связи в базе: подарочные
  коды, созданные им, корректно отвязываются.
- Идентификатор устройства нормализуется в одном месте, иначе одно и то же
  железо попадало в базу в двух написаниях и получало два триала.

## Проверка

- Сервер и клиент собираются без предупреждений.
- Добавлен проект тестов: 37 тестов на правила выдачи триала, пределы срока,
  разделение токенов, одноразовость подарочного кода и проверку версии.
- Миграция базы применена на боевом сервере; перед применением снят дамп.
- Ограничения триала проверены на боевой базе: повторная выдача на то же железо
  и на тот же аккаунт отклоняется.

## Известные ограничения

- Приём оплаты пока не подключён: ключи платёжного провайдера на сервере не
  заданы, создание платежа отвечает отказом. Проверка суммы в уведомлении об
  оплате будет добавлена вместе с подключением реального провайдера.

## Установка

Скачайте `NitroFrameInstaller.exe` во вкладке Assets этого релиза.
